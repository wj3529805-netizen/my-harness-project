# Mac 实机路线图

## 分工与规则

用户和云端审核方负责制定计划。Mac 端 Codex 在 Mac M4 Max、Lightroom Classic 测试 catalog 和 Nikon Z6 III NEF 存储卡上，一次只做下列一项并验证；可以提出建议，但不得自行开始新项目。每项完成后推送到 `mac/<item-id>` 分支（例如 `mac/R1`），不要直接推送到 `phase1`；由云端审核后合并。推送仍须先取得用户授权，也须遵守当时适用的仓库规则。

失败就停止，如实记录现象、错误和未完成的验收，不伪造结果；Mock 或 Linux 的结果不能当作 Mac 或真实 Lightroom 验证。测试失败应按 [KNOWN_RISKS.md](KNOWN_RISKS.md) 如实记录。源卡始终只读，目标文件不能覆盖；“核验通过”指从目标重新读取字节并比对 SHA-256。

全局禁止事项：

- 不改生产 Lightroom catalog，不直接读写 `.lrcat`。
- 不连接生产 NAS。
- 不自动清卡，不删除存储卡文件，也不写入、重命名或修改其权限。
- 不覆盖 RAW，不修改已有 XMP/ACR 侧车文件。
- 不上传真实客户照片。
- 不提交密钥。
- 闭源核心不引入 GPL 代码。
- 不运行未审核的安装脚本。
- 不把鼠标点击自动化当核心方案。
- AI 照片工具保持只接受注册 ID，不提供任意路径、shell、删除或批准工具。
- 推送、付费服务、系统级安装、额外凭据和破坏性操作都需用户授权。

每项按目标、前置条件、步骤要点、验收标准、证据位置、禁止事项、是否需要用户授权记录；证据目录使用小写编号，如 `evidence/mac-r1/`。这些是未来执行时创建的目录，不表示目前已有证据。新脚本如确有必要，只能建议由 Mac Codex 在该分支提出，先审核再决定是否使用。

| 项 | 名称 | 需要用户授权？ |
|---|---|---|
| R1 | Mac 上真实 AI 会话 | 是：DeepSeek 付费用量、Node/Harness 依赖安装 |
| R2 | 外置 exFAT 目标 | 是：选择和使用的盘、格式化，以及可选 SMB 测试共享的指定 |
| R3 | 整卡吞吐 | 默认用用户自己的非客户测试卡；客户卡需授权且不属于本项默认范围 |
| R4 | 拔卡与可选断电 | 是：指定测试卡；真实断电另需授权 |
| R5 | 真实客户数据前的清理 | 是：许可证处置、是否改写历史、最终放行 |

开始前参考 [规格](SPEC.md)、[Mac 交接](MACOS_HANDOFF.md)、[Mac 验证记录](MACOS_VALIDATION.md)、[设备验证记录](MACOS_DEVICE_VALIDATION.md)、[数据流](DATA_FLOW.md)、[完整计划](FULLPLAN.md) 和 [Harness 说明](../harness/README.md)。既有 Mac 真实 Lightroom 合并后完整流程已有有限样本验证；真实 DeepSeek 与 Harness 在 Mac 上结合真实 Lightroom 仍待验证。先用 `bash scripts/mac/check_env.sh` 做只读环境检查；该脚本不安装依赖。

## R1：Mac 上真实 AI 会话

- **目标：** 在测试 catalog 上，用真实 DeepSeek 和受限 Harness 完成规划 → 人工批准 → 执行 → 核验。
- **前置条件：** 独立测试 home、库、预览目录和测试 catalog；测试素材；Python 3.13 项目环境及 Node ≥ 24.9；Harness 固定提交 `ce7073d51254c26cd63b22a60835b8f948deb447`。取得付费 API 和依赖安装授权，审阅依赖及安装步骤。密钥仅通过环境变量 `DEEPSEEK_API_KEY` 提供，另设置 `CETACEA_HOME`；不要把密钥写入命令记录、日志或提交。Harness 是实验性软件。
- **步骤要点：** 核对并必须应用 [受限补丁](../harness/cetacea-restricted.patch.yml)；现有 `harness/run_session.sh <mock|deepseek>` 会叠加该补丁，真实会话用 `harness/run_session.sh deepseek`，按 [Harness 说明](../harness/README.md) 逐行输入 JSON 任务。限制并记录模型请求数。使用 `photo_plan_import` 提供预设 ID 形成完整计划，记录任务 ID 和计划摘要；验证批准前执行及越权请求被拒绝。由人审阅计划后，通过 CLI `approve` 提供任务 ID 和准确摘要；再让 AI 通过 `photo_execute_import` 执行，用 CLI `verify-preview` 和任务结果检查。
- **验收标准：** AI 在 `WAITING_APPROVAL` 停下等待，不能自行批准；批准前执行和删除、shell 等越权请求被拒绝，且无越权操作。批准只由人通过 CLI `approve` 完成；任务最终 `COMPLETED`，`verify-preview` 为 `OK` 且 `mock=false`。保存计划、审批、任务、核验和拒绝的可检查记录，以及实际模型请求数；对目标文件重新读回并比对 SHA-256。失败或无法证明任何一项则记录失败并停止。
- **证据位置：** `evidence/mac-r1/`。提交前在本机检查证据目录，例如先确认环境变量非空，再运行 `grep -rFl -- "$DEEPSEEK_API_KEY" evidence/mac-r1/`；此命令只列出匹配文件名，不输出密钥值。另检查常见密钥前缀和日志、变更内容；发现泄漏则停止，安全处理并重新检查，不提交泄漏内容。
- **禁止事项：** 不让 AI 批准；不使用生产 catalog 或客户照片；不记录密钥，不将 Mock 结果冒充真实 Lightroom。
- **是否需要用户授权：** 是，DeepSeek 付费 API 用量及 Node/Harness 依赖安装；其他全局授权要求同样适用。

## R2：外置 exFAT 目标

- **当前状态（2026-11-03）：** **PASS_IN_SCOPE，单样本**。原始 `2a8d669` / `evidence/mac-r2/` 因 AppleDouble `._*.jpg` 被 `preview.verify` 计为 orphan 而 FAIL_STOPPED；修复 `fdfce5a` 后首次重跑仅在验收脚本解析 `._preview-manifest.json` 时停止（产品 verify 为 OK）。[第二次重跑](../evidence/mac-r2-rerun2/result.json) 在真实 ExFAT SD 上以 **MOCK Lightroom** 通过 ENOTSUP/重试/重复/冲突检查（发布 7 次、预览复用 1 次真实 ENOTSUP），另有独立真实 Lightroom ExFAT 冒烟（曝光读回 0.5、1600×1065）。`NIKON001.DSC` 未变，付费 API 0 次；SMB、整卡及生产可靠性未由此验证。详见 [报告](MACOS_VALIDATION.md)。
- **目标：** 在外置 exFAT 测试目标验证导入、清单 manifest 和预览发布；可选验证用户指定的 SMB 测试共享。
- **前置条件：** 用户明确指定可使用的盘，若需格式化须另获授权；空间充足，源卡只读，库和预览位置隔离。可选 SMB 共享必须由用户指定，绝不能是生产 NAS。
- **步骤要点：** 在目标上完成导入和预览，检查导入 manifest 与预览清单。按照 [copier.py](../src/cetacea/ingest/copier.py) 和 [core.py](../src/cetacea/core.py) 分别检查导入发布及预览重试发布的硬链接不支持回退：后者需要已有成功预览且导出阶段失败后重试。收集实际文件系统返回 `ENOTSUP` 和进入相应回退的证据；若无法实际触发，记为未验证，不以模拟代替。重复导入相同文件，并在隔离测试目标准备不同内容的同名冲突。
- **验收标准：** 导入和预览清单与实际文件对应，目标文件重新读回 SHA-256 一致；两处要求的 `ENOTSUP` 回退均真实走到并有证据。相同文件复核后跳过，不同内容冲突被报告，原目标字节不变。回退使用目标锁协调本工作台写入；不遵守该锁的外部写入者仍可能竞争，须记录这一限制。
- **证据位置：** `evidence/mac-r2/`，包括文件系统信息、实际错误及回退记录、清单、读回哈希和冲突前后对比。
- **禁止事项：** 不碰生产 NAS，不格式化未经授权的盘，不覆盖已有目标或修改源卡。
- **是否需要用户授权：** 是，选择和使用哪块盘、任何格式化，以及可选 SMB 共享的指定。

## R3：整卡吞吐

- **目标：** 测量完整 Nikon Z6 III 测试卡导入速度及资源占用，覆盖 HE 和 HE★ NEF 子类型。
- **前置条件：** 用户自己的非客户测试卡，确认两种子类型均在卡内；目标空间充足。客户卡不属于默认范围，即使考虑使用也须先获用户授权。
- **步骤要点：** 只读清点整卡文件列表、SHA-256 和 mtime；完整导入后再清点对比。记录数据量、总耗时、计算方式、MB/s、峰值内存，以及每个目标文件重新读回的 SHA-256。记录子类型的识别依据。
- **验收标准：** 全卡均被清点，HE 和 HE★ 均有可核查依据；每个应导入文件的目标读回哈希与源一致，耗时、MB/s 和峰值内存有原始记录；源卡前后文件列表、哈希和 mtime 一致。任何漏项或不一致都如实记为未通过。
- **证据位置：** `evidence/mac-r3/`，保存脱敏清单、哈希对比、计时和内存记录。
- **禁止事项：** 不使用真实客户照片，不写卡、不清卡，不以文件大小代替哈希核验。
- **是否需要用户授权：** 默认使用用户自己的非客户测试卡；若拟用客户卡需用户授权，并须先改变本项默认范围及遵守全局限制。

## R4：拔卡与可选断电

- **目标：** 验证拷贝途中拔卡后的安全性和恢复；可选杀进程或经授权的真实断电。
- **前置条件：** 用户指定非客户测试卡；确认测试设备及隔离目标，记录源卡文件列表、哈希和 mtime；先取得计划的人工批准。真实断电必须另获用户同意。
- **步骤要点：** 确认拷贝正在进行后拔卡，保留当时任务和文件状态；可选进行杀进程场景。必要时按现有 CLI `recover` 恢复过期租约；重新连接同一张卡并核对源内容。根据实际状态使用 `retry` 或 `execute` 恢复，保留原批准记录并检查最终读回哈希。
- **验收标准：** 不发布半截最终文件；临时文件被清理或隔离且有记录；任务如实为 `FAILED` 或恢复后为 `PAUSED`，不得伪报完成。原计划未变时重试完成且无需重新批准，目标读回哈希一致；源卡前后列表、哈希和 mtime 一致。各中断方式分别记录结果，不把拔卡结果当作断电结果。
- **证据位置：** `evidence/mac-r4/`，保存中断时刻、状态、临时和最终文件检查、审批记录、重试和源卡对比。
- **禁止事项：** 不向卡写入或删除文件；未经同意不做真实断电；不改计划后沿用旧批准。
- **是否需要用户授权：** 是，指定测试卡；真实断电另需授权。

## R5：真实客户数据前的清理

**状态：** 已在 `prep/R5` 完成样片替换和当前树脱敏，见 [最终验收](FINAL_ACCEPTANCE.md)。所有者选择公开仓库、不重写历史，并已决定样片许可和保留标识的处置；合并到 phase1：见提交记录。真实客户数据尚未放行。

- **目标：** 在考虑真实客户数据之前，处理证据隐私、样片许可证和数据流决定。
- **前置条件：** 清点已提交证据中的 `<HOME>/...` 绝对路径和卷 UUID；[Mac 验证记录](MACOS_VALIDATION.md) 中许可证冲突的旧样片已退出新验证，由 [samples/](../samples/README.md) 的所有者提供样片替代；新样片许可见 [samples/LICENSE.txt](../samples/LICENSE.txt)，旧样片冲突仍未解决。
- **步骤要点：** 清除现有证据中这些标识，或明确记录用户接受的保留策略；不改变证据语义，保留原始哈希或在文档中说明脱敏内容和方法。提出样片许可证处置方案供用户决定。核对 [数据流](DATA_FLOW.md)：用户于 2026-11-02 已接受 DeepSeek 接收 ID、文件名、哈希、状态，以及 `photo_list_sources` 返回的存储卡绝对路径；绝不发送照片像素。确认后再请用户决定是否进入真实客户数据阶段。
- **验收标准：** 清点范围及每处处理或接受策略可检查；脱敏说明或原始哈希可追溯且不歪曲结果；许可证矛盾有用户确定的处置及记录；数据流决定和最终放行决定有记录，未获放行则不进入真实客户数据阶段。
- **证据位置：** `evidence/mac-r5/`，保存清点、脱敏说明、许可证及决定记录，不包含密钥或客户照片。
- **禁止事项：** 不篡改证据语义；未经用户授权不改写 git 历史；不发送照片像素。
- **是否需要用户授权：** 是，许可证处置、是否改写 git 历史，以及进入真实客户数据的最终放行。
